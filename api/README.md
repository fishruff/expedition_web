# Сервис приёма событий

Принимает события от плагина ExpeditionCore, складывает их в журнал и раз в минуту
пересобирает снимки, которые читает сайт. Форматы — в [`../docs/contract/api-v1.md`](../docs/contract/api-v1.md).

## Запуск

```bash
EXPEDITION_KEY=secret-key npm run api
```

Запускается через `tsx`, а не голым `node`. Собственное разбирательство TypeScript у Node
появляется только в официальных сборках 22.18 и новее — на Node из репозитория Ubuntu
его нет вовсе, и `node api/src/main.ts` падает с «Node.js is not compiled with TypeScript
support». Зависеть от того, чьей сборкой запущен сервис, не хочется.

| Переменная | По умолчанию | Зачем |
| --- | --- | --- |
| `EXPEDITION_KEY` | — | Секрет, которым подписывается каждый запрос плагина. Обязателен |
| `PORT` | `4000` | Порт приёма |
| `EVENT_LOG` | `data/events.jsonl` | Журнал событий |
| `DATA_DIR` | `public/data` | Куда писать снимки для сайта |
| `SEASON_STARTS_AT`, `SEASON_STORY_ENDS_AT` | — | Даты сезона: событиями они не приходят |

**Ключ обязан быть из латиницы и цифр.** Заголовки HTTP не переносят не-ASCII, кириллический
ключ доедет искажённым, и приём будет молча отвечать «неверный ключ». Проверено на живом
сервисе, поэтому сервис теперь падает на старте, а не молчит.

## Как устроено

**Журнал вместо базы.** События дописываются в `events.jsonl` по одному на строку. За сезон
это несколько десятков тысяч строк — пара мегабайт. Журнал переживает перезапуск, читается
глазами и позволяет пересобрать снимки заново в любой момент.

**Снимки пересобираются целиком**, а не правятся по месту: `applyEvents` сводит весь журнал
за раз. При наших объёмах это миллисекунды, зато нет ни одного состояния, которое можно
испортить частичным обновлением.

**Запись атомарная** — во временный файл и переименование. Иначе сайт может прочитать
половину файла, если запрос застал запись на середине.

## Проверка

```bash
curl http://localhost:4000/health
curl -X POST http://localhost:4000/events -H 'X-Expedition-Key: secret-key' \
  -d '{"id":"e1","v":1,"type":"server.heartbeat","at":"2026-10-20T21:00:00Z","online":[]}'
```

Повторная отправка того же события отвечает успехом с пустым `accepted` — плагин имеет
право слать одно и то же сколько угодно раз.
