# ExpeditionCore — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Написать плагин Paper, который замечает происходящее в игре и надёжно доставляет
это в `api` — так, чтобы ни одно событие не потерялось при падении сети, перезапуске сервера
или недоступности приёмника.

**Architecture:** Слушатели и планировщики на главном потоке собирают неизменяемые события
и кладут их в очередь. Отдельный поток ввода-вывода пишет очередь на диск и отправляет её
в `api`. Ни одно обращение к сети или диску не происходит на главном потоке. Всё, что можно
написать без Bukkit, написано без Bukkit и покрыто JUnit.

**Tech Stack:** Java 21, Paper API 1.21, Gradle (Kotlin DSL), JUnit 5. Внешних зависимостей нет:
HTTP — встроенный `java.net.http`, JSON собирается вручную, текст книг — Adventure с classpath
сервера. Gson там же лежит, но за два десятка строк сборки JSON платить связью с чужой сборкой
не стоит: опасное место в ней одно — экранирование, и оно покрыто тестами.

Спека: [`docs/superpowers/specs/2026-08-17-expedition-core.md`](../specs/2026-08-17-expedition-core.md).
Контракт: [`docs/contract/api-v1.md`](../../contract/api-v1.md).

## Global Constraints

Требования ниже действуют для каждой задачи и не повторяются в них отдельно.

- **На главном потоке — ни одного обращения к сети и диску.** Слушатель собирает событие
  и кладёт его в очередь, дальше не его дело. Нарушение видно игрокам как лаг.
- **Класс, который можно написать без Bukkit, пишется без Bukkit** и покрывается JUnit.
  Слушатели и команды логики не содержат: прочитать, собрать событие, положить в очередь.
- **Событие неизменяемо** — `record`, собранный один раз. Общего изменяемого состояния между
  потоками нет вообще, только очередь.
- **`id` события — `UUID.randomUUID()`**, выдаётся в момент создания и при повторной отправке
  не меняется. На этом держится вся защита от повторов: `api` отбрасывает знакомые номера.
- **`at` — всегда UTC, ISO-8601, с миллисекундами**: `Instant.now().truncatedTo(MILLIS)`.
  Не до секунд: `api` сортирует по `at`, и при равном времени первенство находки решает
  случайность прихода.
- **Тексты игроку — на русском**, в стилистике экспедиции. Ошибки объясняют, что делать,
  а не что произошло: «подпиши книгу, заголовок станет названием записи».
- **Плагин не занимается авторизацией.** Вход закрывают ванильный `white-list` и сторонний
  плагин пароля: сервер в `online-mode=false`, и `uuid` там есть функция ника — человека он
  не удостоверяет. Подсистема, умеющая запереть всех снаружи, не живёт в одном плагине
  с телеметрией находок.
- **Статистику считает ваниль, а не мы.** Свой счётчик пришлось бы слать приростом, а прирост
  требует, чтобы не потерялось ни одно событие. Исключение одно — поставленные блоки: их
  ванильного счётчика не существует.
- **В лог только через `getLogger()`**, никаких `System.out`.
- **Ключ никогда не попадает в лог и в сообщения об ошибках** — ни целиком, ни куском.
- Форма событий меняется только вместе с `docs/contract/api-v1.md` и `api/src/events.ts`.
  Это одна правка в трёх местах и один коммит.

## Этап 1. Труба: конфиг, очередь, отправка

Смысл этапа — довести до работы всё, что не зависит от игры. Проверяется против живого `api`
без единого игрока на сервере.

- [x] Дописать в `build.gradle.kts` JUnit 5 (`testImplementation`, `tasks.test { useJUnitPlatform() }`).
      Сейчас тестового набора нет вообще.
- [x] `Settings` и `ConfigManager`: адрес `api`, таймаут, периоды сигнала, слепка и обхода.
      Ключ берётся **только из переменной окружения** `EXPEDITION_KEY` — в конфиге, который
      уедет в репозиторий или в архив с бэкапом, секрету не место.
- [x] **Плагин отключает сам себя на старте**, если ключ пуст или содержит не-ASCII, с понятным
      сообщением в лог. Заголовки HTTP не переносят кириллицу: ключ доедет искажённым, и обмен
      будет молча отвечать «неверный ключ». Эту ошибку уже поймали живьём на стороне `api` —
      второй раз искать её на репетиции незачем.
- [x] `Event`, `Events`, `EventJson`. Тесты: форма каждого из девяти событий контракта,
      экранирование кавычек и переносов, `at` в UTC с миллисекундами.
- [x] `Backoff`: 5с, 15с, 60с, дальше раз в минуту. Сбрасывается после успеха. Тест на всю лестницу.
- [x] `SendOutcome` и правила разбора ответа. Тесты на каждое:
      - `200` — **вся отправленная пачка доставлена, независимо от `accepted`**;
      - `401` — повторяем, но кричим в лог на каждой попытке;
      - `400` — пачка уезжает в `rejected.jsonl` и выбрасывается из очереди;
      - `413` — делим пополам и пробуем снова;
      - `5xx`, таймаут, отказ соединения — повтор по лестнице отсрочек.
- [x] `Outbox` на своём потоке: положить, записать `outbox.jsonl` целиком, отправить пачкой
      до ста, вычистить доставленное. Тесты: порядок по `at`, переживание перезапуска,
      пустой `accepted` не зацикливает, битое событие не останавливает очередь.
- [x] `HttpEventSender` на `java.net.http`, заголовки `Content-Type` и `X-Expedition-Key`.
- [x] Поднять `Outbox` в `onEnable`, закрыть в `onDisable`: **сначала запись очереди на диск,
      потом попытка отправки не дольше трёх секунд**. Именно в этом порядке.
- [x] Один `server.heartbeat` при включении — первое настоящее событие, ради проверки трубы.
- [x] `/expedition status` (длина очереди, время последней удачной отправки, последняя ошибка)
      и `/expedition flush`. Это не удобство: без них сбой обмена невидим — игра идёт, сайт
      молчит, и непонятно, чья это половина.

**Проверка этапа.** `./gradlew test` зелёный. Живьём: поднять `api` локально, запустить сервер,
увидеть строку в `events.jsonl`. Затем погасить `api`, дождаться, пока очередь накопится,
перезапустить сервер Minecraft, поднять `api` — накопленное должно доехать целиком.

## Этап 3. Статистика

- [x] `Playtime`: **`PLAY_ONE_MINUTE` считает тики, а не минуты**, вопреки названию. Делим на 1200.
      Тест на это первый — из-за этой ловушки время в игре оказывается в шестьдесят раз больше
      настоящего.
- [x] `StatsReader` на главном потоке (ванильная статистика не потокобезопасна):
      расстояние — сумма `WALK`, `SPRINT`, `SWIM`, `BOAT`, `HORSE_ONE_CM`;
      добыто — сумма `MINE_BLOCK` по материалам, с отсевом не-блоков и устаревших, иначе бросает
      исключение; убито и смерти — напрямую.
- [x] `BlocksPlaced`: счётчик в памяти по `BlockPlaceEvent`, поднимается из `PersistentDataContainer`
      игрока при входе и опускается обратно при выходе, на пятиминутном такте и при остановке.
      Ванильного счётчика нет, а сто обращений к диску на сто поставленных блоков не нужны.
- [x] `stats.snapshot` при входе, раз в пять минут для тех, кто в сети, и при выходе. Вход
      добавлен к двум срокам контракта: без него вернувшийся игрок до пяти минут показан
      на сайте нулями, а ноль — это не «данных пока нет», это неправда.

**Проверка этапа.** Карточка игрока на сайте заполняется настоящими числами. Время в игре
сверить с `/stats` в клиенте — это и есть проверка ловушки с тиками.

## Этап 4. Метки, находки, чтение

Сердце сюжетной части.

- [x] `Marks`: ключи `expedition:record` и `expedition:artifact` в PDC предмета. Чтение, запись, снятие.
- [x] Команды оператора: `/expedition record <id>`, `/expedition artifact <id>`,
      `/expedition inspect`, `/expedition unmark`. **`artifact` отвергает не-ASCII прямо в чате**:
      `api` кладёт ключ в разблокировки как есть, а сайт проверяет его буквально, поэтому
      кириллический `хронометр` открыл бы несуществующий раздел молча.
- [x] `SeenState` в `state.txt`: что уже отправлено. Не JSON — своим парсером ради четырёх видов
      строк платить незачем, а так файл читается глазами и чинится руками. Запись уходит на
      другой поток: главный не должен ждать файловую систему. Без него книга в рюкзаке порождала бы
      событие каждые пять секунд. Тесты на чтение, запись и битый файл.
- [x] `InventorySweep` раз в пять секунд: 41 слот у каждого, кто в сети, включая броню и левую руку.
      **Творческий режим и наблюдатель пропускаются** — иначе владелец, раскладывающий книги
      перед сезоном, «найдёт» их все сам.
- [x] `ReadWatcher`: правый клик подписанной книгой с меткой → `record.read`. Пара «книга плюс
      игрок» помнится, чтобы десять кликов не стали десятью событиями.

**Проверка этапа.** Пометить книгу в креативе, положить в сундук, переключиться в выживание,
забрать — находка появляется в архиве на сайте. Одного аккаунта достаточно: обход пропускает
креатив, поэтому находкой считается именно переход в выживание с книгой на руках.

Отдельно проверить, что потеря `state.txt` не портит снимки: удалить файл, дождаться обхода,
убедиться, что запись на сайте осталась за первым нашедшим. Повторная находка превращается
в прочтение, а прочтение нашедшим не засчитывается — это следует из кода `api`, и тем ценнее
увидеть это живьём.

## Что проверяется автоматически

`./gradlew test` — только чистые классы, зато целиком:

| Класс | Что проверяется |
| --- | --- |
| `EventJson`, `Events` | Форма девяти событий, экранирование, время в UTC |
| `Backoff` | Лестница отсрочек, сброс после успеха |
| `Outbox` | Порядок, перезапуск, пустой `accepted`, `400`, `413`, пачка в сто |
| `SeenState` | Чтение, запись, битый файл |
| `NoteValidator` | Страницы, знаки, двадцать в сутки, граница суток |
| `Playtime` | Тики в минуты |
| `Zones` | Точка в коробке, границы, ничья, смена зоны |
| `Settings` | Пустой ключ, не-ASCII, значения по умолчанию, разбор коробок |

Слушатели и команды не тестируются намеренно: в них нет логики, которую можно сломать,
а поднятый ради них Bukkit стоит дороже, чем ловит.

Поверх — живая проверка против настоящего `api` на каждом этапе. Она ловит то, чего не поймает
ни один модульный тест: заголовки, кодировку, формат времени, недоступность.

## Порядок и почему он такой

Этапы не переставлять. Первый доводит трубу до работы там, где нет ни игроков, ни сюжета —
самое дешёвое место для отладки. Второй делает так, что **сайт начинает показывать правду**,
и всё дальнейшее видно глазами. Всё, что раньше второго этапа, отлаживается по логам;
всё, что позже, — на экране.

## Открытые вопросы

Решения ниже нужны к четвёртому этапу, кроме первого — он нужен раньше, если ответ «да».

- **Объявлять ли находки и открытые зоны в игровом чате?** «Arsen нашёл первую табличку» —
  одна строка кода, но она превращает находку в событие для всех, а не для одного.
- **Считать ли чтение с кафедры?** Сейчас нет: книга на кафедре доступна всем сразу и превратила
  бы счётчик «позже прочитали семеро» в счётчик посетителей комнаты.
- **Пять секунд на обход инвентарей** — приемлемо? Можно сделать секунду, но выигрыш не виден:
  снимки всё равно пересобираются раз в минуту.
