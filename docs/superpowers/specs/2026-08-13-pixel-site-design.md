# Пиксельный сайт Expedition — дизайн

Дата: 2026-08-13
Статус: утверждён владельцем, готов к планированию реализации
Отменяет: `archive-2026-08-12-photoreal-diary-design.md`

## Задача

Сайт Minecraft-сервера Expedition в пиксельном оформлении. По центру — пиксельная иллюстрация стола
с дневником экспедиции, вокруг — плоские панели интерфейса с содержимым. Компас и карманные часы на
столе кликабельные. Разделы открываются как страницы одного журнала, а не как отдельные вкладки:
сцена остаётся на месте, меняется только содержимое.

Референс оформления: `docs/reference/mockup-pixel-desk.jpg`.

### Почему не фотореализм

Предыдущая спека описывала фотореалистичный кожаный дневник. От неё отказались после дня прототипов:
текст в браузере рисуется отдельным слоем поверх фотографии и читается как наклейка, а фотография
разворота имеет фиксированный размер и не вмещает списки переменной длины. Пиксельное направление
снимает обе проблемы: арт и текст одинаково чёткие, а тайлы и рамки тянутся под любое содержимое.

## Разделы

| Раздел | Маршрут | Содержимое |
| --- | --- | --- |
| Главная | `/` | Закрытый дневник, адрес сервера, онлайн, ближайший ивент |
| Журнал | `/log` | Оглавление: список записей |
| Экипаж | `/crew` | Список участников с головами и статусом |
| Участник | `/crew/:nick` | Арт, ник, соцсети, биография, статистика |
| Летопись | `/news` | Находки и события с датами |
| Устав | `/charter` | Правила сервера |
| Карта | `/map` | Заглушка «карта ещё не начерчена» |
| 404 | `*` | Вырванная страница со ссылкой на оглавление |

Компас на столе ведёт на `/map`, часы — на `/log` с открытым отсчётом.

## Механика оформления

### Целый масштаб

Вся сцена живёт в CSS-переменной `--s` — целом числе от 1 до 4, которое считается от ширины окна
(`src/scene/useScale.ts`, уже реализовано). Размеры задаются функцией `px(n)`, где `n` — точки
исходника. Дробный масштаб запрещён: пиксель-арт от него мылится.

### Три типа ассетов

Это ответ на вопрос адаптива, и каждый ассет обязан быть одного из трёх типов.

| Тип | Поведение | Примеры | Механизм |
| --- | --- | --- | --- |
| Тайл | повторяется, заполняет любой размер | дерево стола, бумага страниц | миксин `tile()` |
| Рамка из девяти слоёв | тянется под содержимое, углы целы | панели, книга, кнопки | миксин `nine-slice()` |
| Предмет | не тянется, только целый масштаб | компас, часы, лампа, арт игрока | `<img>` + `crisp` |

Следствие, важное для контента: книга собрана из рамки и тайла бумаги, поэтому она резиновая. Список
любой длины помещается — прокруткой внутри страницы или разбиением на развороты с листанием.

### Постоянная сцена

`Desk` — layout-роут, он рендерится один раз и при навигации не перерисовывается. Меняется только
содержимое центрального слота. Переход между разделами сопровождается ступенчатой анимацией
перелистывания; URL при этом меняется, кнопка «назад» работает.

При прямом заходе по ссылке на раздел сцена рендерится сразу в нужном состоянии, без интро.

## Раскладка

Три режима, различаются составом, а не только шириной колонок.

**Широкий экран (от `lg`).** Три колонки: левая панель, центр со сценой, правая панель. На столе
видны компас, часы, лампа и мелкий реквизит. Сверху полоса с логотипом, навигацией и счётчиком
онлайна, снизу — узкая полоса с ссылками.

**Планшет (`md`–`lg`).** Масштаб падает на ступень. Боковые панели сужаются, мелкий реквизит
скрывается, компас и часы остаются.

**Телефон (до `md`).** Предметы скрываются полностью — они декоративные. Книга разворачивается в одну
страницу во всю ширину, панели уходят под неё вертикальным списком. Навигация сворачивается в
хотбар — горизонтальный ряд слотов с иконками разделов.

## Архитектура

```
src/scene/
├── Desk/            стол: фон-тайл, сетка, слоты        (есть)
├── useScale.ts      целый масштаб сцены                 (есть)
├── Prop/            предмет на столе: картинка + подсветка + подпись
└── props.ts         описание предметов: файл, размер, маршрут, подпись

src/ui/
├── Panel/           рамка из девяти слоёв + заголовок
├── Book/            книга: рамка + тайл бумаги + слот содержимого
├── Slot/            слот хотбара с иконкой
└── Countdown/       живой отсчёт на данных из shared/lib

src/sections/        по папке на раздел, чистые компоненты над данными
├── Home/ Log/ Crew/ CrewMember/ News/ Charter/ MapStub/ TornPage/
```

Границы: `Prop`, `Panel`, `Book`, `Slot` ничего не знают о данных и разделах. Разделы ничего не знают
о масштабе и ассетах. Замена арта — это замена файлов в `public/assets`, без правок разметки.

## Данные

Слой контента из предыдущей спеки сохраняется без изменений: JSON в `src/content/` плюс валидация,
которая отбрасывает битые записи. Добавляется файл `charter.json`.

Структура участника расширяется под страницу игрока:

```jsonc
{
  "nick": "Arsen",
  "title": "штурман",
  "art": "/assets/crew/arsen.png",
  "bio": "Ведёт экспедицию по компасу и звёздам.",
  "joinedAt": "2026-03-14",
  "socials": { "discord": "…", "telegram": "…", "youtube": null, "twitch": null },
  "stats": { "hours": null, "blocks": null, "distanceKm": null, "deaths": null, "lastSeen": null }
}
```

Поля в `stats` заполняются с сервера и на старте равны `null`. Компонент обязан показывать прочерк
вместо пустого места — верстка не должна прыгать, когда данные появятся.

**Про источник статистики.** Ванильный Minecraft наружу статистику не отдаёт: официальный API Mojang
знает только ник, UUID и скин. Часы, блоки и смерти лежат в файлах статистики на сервере, и нужен
плагин или скрипт, выгружающий их в JSON. До этого момента поля остаются `null`. Онлайн игроков
получается пингом сервера и делается отдельной задачей.

## Ассеты

Хранятся в `public/assets`, в родном размере, только PNG.

| Файл | Тип | Размер | Требование |
| --- | --- | --- | --- |
| `wood-tile.png` | тайл | 32×32 | бесшовный по всем сторонам |
| `paper-tile.png` | тайл | 32×32 | бесшовный, светлый, ровный |
| `frame-book.png` | рамка | 96×96 | углы 24, середина прозрачная |
| `frame-panel.png` | рамка | 48×48 | углы 12, середина заполнена |
| `compass.png` | предмет | ~128×96 | прозрачный фон |
| `watch.png` | предмет | ~70×110 | прозрачный фон |
| `lamp.png` | предмет | ~80×120 | прозрачный фон |
| `prop-*.png` | предмет | разные | мелкий реквизит: свитки, перо, сундук |
| `crew/<nick>.png` | предмет | 64×96 | арт участника, прозрачный фон |

Сейчас в репозитории лежат временные заглушки, нарисованные кодом. Настоящий арт заменяет их
пофайлово, без правок кода.

Шрифт — Monocraft (OFL, кириллица), файлы в `public/fonts`, обращений к сторонним CDN нет.

## Крайние случаи

| Ситуация | Поведение |
| --- | --- |
| Раздел без данных | «Эта страница ещё не заполнена» |
| У участника нет арта | Силуэт-заглушка того же размера, вёрстка не смещается |
| Статистика не подключена | Прочерк вместо числа, подпись «данных пока нет» |
| Ивентов нет | Отсчёт скрыт, подпись «Штиль» |
| Неизвестный маршрут или ник | Вырванная страница со ссылкой на оглавление |
| Ассет не загрузился | `alt`-текст на месте картинки, раскладка не ломается |
| `prefers-reduced-motion` | Ступенчатые анимации отключаются |
| Экран уже `sm` | Предметы скрыты, книга в одну страницу, панели вертикально |

## Тестирование

Существующие тесты сохраняются: валидация контента, склонения, отсчёт, выбор ивента, расчёт масштаба.

Добавляется:

- смоук на каждый раздел — рендерится и не падает на пустых данных;
- `Panel` и `Book` растягиваются под содержимое (проверяется наличие потомков, не пиксели);
- `Prop` рендерит подпись и ведёт по нужному маршруту;
- статистика с `null` показывает прочерк, а не пустоту.

Внешний вид и пиксельная чёткость тестами не покрываются — проверяются глазами.

## Границы работы

Входит: сцена, панели, книга, предметы, навигация, восемь разделов, адаптив на три режима,
подключение реального арта по мере поступления, тесты перечисленной логики.

Не входит: магазин, вики, реальная карта мира, авторизация, админка, выгрузка статистики на стороне
сервера, виджет онлайна (отдельной задачей после появления реального IP).
