# Сайт-дневник Expedition — дизайн

Дата: 2026-08-12
Статус: утверждён, готов к планированию реализации

## Задача

Сайт Minecraft-сервера Expedition подаётся как кожаный дневник, лежащий на столе поверх карты.
Дневник открывается по клику, внутри — записи, ведущие на разделы сайта. Рядом с дневником лежат
компас (открывает карту) и карманные часы (обратный отсчёт до ивента).

Текущий каркас проекта (React 19, Vite 8, SCSS-модули, react-router 8) сохраняется. Тёмно-зелёная
тема и страницы-заглушки из первоначального scaffold заменяются целиком.

## Разделы

Из первоначального набора остаются три записи; магазин, вики и «как начать» из навигации убираются.

| Запись | Маршрут | Содержимое |
| --- | --- | --- |
| Экипаж | `/crew` | Карточки участников сервера |
| Участник | `/crew/:nick` | Арт игрока и его описание |
| Новости экспедиции | `/news` | Лента находок и событий с датами |
| Устав экипажа | `/charter` | Правила сервера |
| Карта | `/map` | Разворот с надписью «Карта ещё не начерчена». Реальную карту подключим отдельной задачей |

Плюс два служебных состояния: `/` — закрытая обложка, `/log` — разворот-оглавление.

## Взаимодействие

Сцена стола постоянна: она рендерится один раз и не перерисовывается при навигации. Меняется только
содержимое разворота.

1. `/` — дневник закрыт. На обложке тиснение «EXPEDITION», на вшитой бирке — IP сервера и версия.
2. Клик по обложке → анимация раскрытия (поворот обложки вокруг левого края) → `/log`.
3. `/log` — разворот-оглавление со списком записей. Клик по записи → лист поворачивается поверх
   разворота, под ним новый контент.
4. Кнопка «назад» в браузере работает на каждом шаге: URL меняется на всех переходах.

**Прямой заход по ссылке.** При загрузке любого маршрута кроме `/` дневник рендерится уже открытым,
без интро-анимации. Анимация раскрытия проигрывается только при переходе `/` → `/log` внутри сессии.
Иначе каждая расшаренная ссылка заставляет ждать анимацию.

## Архитектура

```
DeskScene (layout-роут)        стол, карта, виньетка; сетка: слева · центр · справа
├─ Compass                     SVG, стрелка покачивается, ведёт на /map
├─ Diary                       книга: обложка + текущий разворот
│  ├─ DiaryCover               лицевая сторона: название, IP, версия
│  └─ DiarySpread              левый и правый лист, внутрь идёт <Outlet />
└─ PocketWatch                 SVG-часы + обратный отсчёт
```

Границы ответственности:

- **`Diary`** — единственное место, где живут `perspective`, `rotateY` и управление состоянием
  открыт/закрыт. Разделы про 3D ничего не знают: они отдают контент, который `DiarySpread`
  раскладывает по листам. Смена подхода к анимации (на полноценное перелистывание книги) затрагивает
  только этот компонент.
- **`DeskScene`** — раскладка сцены и ничего больше. Не знает, какой раздел открыт.
- **Развороты** (`TableOfContents`, `CrewSpread`, `CrewMemberSpread`, `NewsSpread`, `CharterSpread`) —
  чистые компоненты над данными, тестируются в отрыве от сцены.
- **`Compass` и `PocketWatch`** — самостоятельные виджеты, зависят только от своих данных.

Предметы на столе — часть сетки, а не абсолютно спозиционированный декор поверх. На широком экране
три колонки, на узком — дневник во всю ширину, компас и часы в нижней панели.

## Анимации

Выбранный подход: 3D тратится только на раскрытие обложки — самый ценный момент — а смена разворотов
делается одним поворачивающимся листом.

| Переход | Реализация | Длительность |
| --- | --- | --- |
| Раскрытие обложки | `rotateY(-180deg)`, `transform-origin: left` | 700 мс |
| Смена разворота | один лист поворачивается поверх, под ним новый контент | 450 мс |
| Наведение на предмет | подъём тени, лёгкий поворот | 200 мс |

При `prefers-reduced-motion: reduce` все повороты заменяются на fade 150 мс. Полноценное
перелистывание каждого листа (стопка страниц с управлением z-index) сознательно не делаем: оно даёт
малую прибавку к эффекту при трёхкратной трудоёмкости и рисках на слабых устройствах.

## Данные

Контент лежит в `src/content/` и импортируется на этапе сборки. Бэкенда нет. Админка возможна позже —
тогда меняется только слой доступа к данным, компоненты не трогаются.

```jsonc
// crew.json
{ "nick": "Steve", "title": "Штурман", "art": "/crew/steve.png",
  "description": "Первым нашёл храм в джунглях…", "joinedAt": "2026-03-14" }

// news.json
{ "id": "artifact-compass", "date": "2026-08-10", "title": "Найден компас Древних",
  "text": "…", "author": "Steve" }

// events.json
{ "title": "Гонка за артефактом", "startsAt": "2026-08-20T18:00:00+03:00",
  "endsAt": "2026-08-27T23:59:00+03:00" }
```

Между JSON и компонентами — слой `src/content/index.ts`:

- отбрасывает записи без обязательных полей (`nick` у участника, `id` и `date` у новости);
- сортирует новости по дате, новые первыми;
- выбирает ближайший ивент из списка.

Одна кривая запись не роняет раздел. Битый JSON ломает сборку — это правильная сторона провала:
ошибка видна до деплоя.

Данные сервера (название, IP, версия, ссылки) остаются в `src/shared/config/site.ts`.

## Палитра и типографика

Тёплая, малоконтрастная — свет лампы на дереве. Цвета задаются CSS-переменными в `global.scss`.

| Назначение | Цвет |
| --- | --- |
| Стол, дерево | `#2a1d14` |
| Кожа обложки | `#5a3a22`, тени `#3f2817` |
| Бумага | `#e8dcc0`, у корешка `#d9c9a3` |
| Чернила | `#2e2418` |
| Чернила выцветшие | `#5c4b33` |
| Латунь: компас, часы, ссылки | `#b8863b` |
| Сургуч: акценты, ошибки | `#8c2f22` |

Текстуры кожи, бумаги и дерева — градиенты и SVG-шум, без растровых картинок. Компас и часы —
векторные. Единственная растровая графика на сайте — арты участников.

Арты генерируются нейросетью по скинам игроков, то есть приходят пачками в едином стиле и
предсказуемого размера. Поэтому на развороте участника арт — портрет фиксированных пропорций 3:4 в
рамке под старую фотокарточку, с наклоном на пару градусов и тенью, будто вклеен в дневник. Файлы
лежат в `public/crew/<nick>.png`, требование к исходнику — не меньше 600×800.

Шрифты: рукописный на заголовки записей и подписи, антиква на основной текст. Файлы лежат в
`public/fonts` и раздаются со своего домена, без обращений к сторонним CDN. До того как файлы
появятся, работает системная антиква — вёрстка от этого не зависит.

## Крайние случаи

| Ситуация | Поведение |
| --- | --- |
| Раздел без данных | «Эта страница ещё не заполнена» тем же почерком |
| У участника нет арта | Силуэт в рамке, вёрстка не смещается |
| Ивентов нет | Часы идут, подпись «Штиль» |
| Ивент впереди | «До начала: …» |
| Ивент идёт | «До конца: …» |
| Ивент закончился | Выбирается следующий; если такого нет — «Штиль» |
| Неизвестный маршрут | Вырванная страница с рваным краем и ссылкой на оглавление |
| Неизвестный `:nick` | То же, что и 404 |
| `prefers-reduced-motion` | Повороты заменяются на fade 150 мс |
| Узкий экран | Один лист, предметы в нижней панели |

## Тестирование

В проекте нет тест-раннера — ставим vitest и @testing-library/react.

Покрываем логику, где легко ошибиться:

- выбор ближайшего ивента: идёт сейчас, весь в прошлом, весь в будущем, список пуст;
- обратный отсчёт: склонения «1 день / 2 дня / 5 дней», переход через полночь, часовые пояса;
- фильтрация битых записей: запись без обязательного поля отбрасывается, остальные остаются;
- сортировка новостей по дате.

Плюс смоук-тест на каждый разворот: рендерится и не падает на пустых данных.

Анимации и 3D-трансформации тестами не покрываем — проверяются глазами.

## Границы работы

Входит: сцена стола, дневник с раскрытием, пять разворотов (оглавление, экипаж, участник, новости,
устав), компас-заглушка, часы с отсчётом, адаптив, тесты перечисленной логики.

Не входит: админка, приём платежей, магазин, вики, реальная карта мира, авторизация, интеграция с
API сервера (онлайн игроков). Всё это возможно позже отдельными задачами.
