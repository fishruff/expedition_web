# Контракт обмена Expedition, версия 1

Дата: 2026-08-15
Статус: черновик, обсуждается

Договорённость между тремя частями системы: игровым плагином, сервисом приёма и сайтом.
Обе стороны пишутся отдельно и встречаются только на сборке — поэтому всё, что здесь описано,
менять в одностороннем порядке нельзя.

## Кто с кем разговаривает

```
Paper + ExpeditionCore  ──POST /events──►  api  ──пишет──►  /data/*.json  ──читает──►  сайт
      (контейнер mc)                  (контейнер api)      (общий том)          (контейнер web)
```

Плагин только **отправляет** события. Он никогда ничего не читает у сайта и не знает про сюжет.
Сайт только **читает** файлы. Он никогда не обращается к игровому серверу.

---

## Часть 1. Что заполняешь руками, а что приезжает из игры

Это самая важная таблица во всём документе. Перепутать эти два столбца — главный источник
неразберихи в таких проектах.

| Данные | Откуда берутся | Где лежат |
| --- | --- | --- |
| Тексты сюжетных записей, главы, что открывают | **руками** | `src/content/story.json` |
| Ники, арты, биографии, соцсети, ручные звания | **руками** | `src/content/crew.json` |
| Метки на карте: координаты, названия, описания | **руками** | `src/content/places.json` |
| Устав, даты сезона и событий | **руками** | `src/content/charter.json`, `events.json` |
| Правила выдачи автоматических званий | **руками** | `src/content/titles.json` |
| Кто сейчас в сети | из игры | `/data/status.json` |
| Часы в игре, блоки, мобы, расстояние, смерти | из игры | `/data/crew.json` |
| Кто и когда нашёл запись, сколько прочитали | из игры | `/data/records.json` |
| Записи игроков, написанные книгой | из игры | `/data/notes.json` |
| Что уже разблокировано | из игры | `/data/unlocks.json` |

Правило слияния: **содержание всегда твоё, цифры всегда из игры.** Если запись `храм-1` ещё не
найдена никем, сайт знает её текст, но не показывает — она появится, когда в `records.json`
возникнет строка о находке.

## Часть 2. События от плагина

### Общие правила

Адрес: `POST http://api:4000/events`
Заголовки: `Content-Type: application/json`, `X-Expedition-Key: <секрет из переменной окружения>`
Тело: одно событие или массив событий (пачкой до 100 штук).

Ответ при успехе:

```json
{ "ok": true, "accepted": ["e7f3a1", "e7f3a2"] }
```

**Каждое событие обязано иметь эти четыре поля:**

| Поле | Тип | Смысл |
| --- | --- | --- |
| `id` | строка | Уникальный номер события. Придумывает плагин. Нужен, чтобы отличить повтор от нового события |
| `v` | число | Версия контракта. Сейчас `1` |
| `type` | строка | Что произошло, из списка ниже |
| `at` | строка | Время в формате ISO 8601, **всегда UTC**: `2026-08-15T21:47:03Z` |

Игрок, если событие про него, описывается всегда одинаково:

```json
"player": { "uuid": "069a79f4-44e9-4726-a5be-fca90e38aaf5", "name": "Arsen" }
```

`uuid` — главный ключ. Ник может смениться, `uuid` никогда.

### Как ведём себя при сбоях

- **Повторы.** Если событие с таким `id` уже приходило, `api` его молча игнорирует и всё равно
  отвечает успехом. Плагин имеет право слать повторно сколько угодно.
- **Недоступность.** Если `api` не ответил, плагин **кладёт событие в очередь на диск** и повторяет
  через 5, 15, 60 секунд, дальше раз в минуту. Очередь переживает перезапуск плагина.
  Терять события нельзя: первая находка сезона невосстановима.
- **Неизвестный тип.** `api` принимает событие, записывает в журнал и отвечает успехом.
  Плагин новее сайта — это нормальная ситуация, ломаться нельзя.
- **Порядок.** События могут прийти не по порядку. Всё, что зависит от очерёдности, решается
  по полю `at`, а не по времени прихода.

### Список событий

#### `player.join` и `player.leave`

```json
{
  "id": "3f1a…", "v": 1, "type": "player.join",
  "at": "2026-08-15T18:02:11Z",
  "player": { "uuid": "069a…", "name": "Arsen" }
}
```

#### `server.heartbeat`

Раз в минуту, всегда, даже если на сервере пусто.

```json
{
  "id": "9c22…", "v": 1, "type": "server.heartbeat",
  "at": "2026-08-15T18:03:00Z",
  "online": [
    { "uuid": "069a…", "name": "Arsen" },
    { "uuid": "b2c1…", "name": "Kira" }
  ]
}
```

**Зачем нужен, если есть join и leave.** Если сервер упадёт, событие `leave` не придёт, и сайт
навсегда покажет людей в сети. Список онлайна берётся **только из последнего heartbeat**,
а `join` и `leave` нужны для ленты событий. Если heartbeat не приходил больше трёх минут,
сайт считает сервер выключенным и пишет об этом честно.

#### `record.found`

Сюжетная книга впервые попала в инвентарь игрока.

```json
{
  "id": "a71b…", "v": 1, "type": "record.found",
  "at": "2026-08-15T21:47:03Z",
  "player": { "uuid": "069a…", "name": "Arsen" },
  "recordId": "храм-1"
}
```

**Первенство решает `api`, а не плагин и не сайт.** Первое пришедшее событие для данного
`recordId` становится находкой, все последующие превращаются в `record.read`. Если два события
про одну книгу пришли в одной пачке — побеждает меньшее `at`.

#### `record.read`

Кто-то прочитал уже найденную книгу. Нужно ради строчки «позже прочитали семеро».

```json
{
  "id": "a71c…", "v": 1, "type": "record.read",
  "at": "2026-08-16T09:12:44Z",
  "player": { "uuid": "b2c1…", "name": "Kira" },
  "recordId": "храм-1"
}
```

Пара «запись плюс игрок» уникальна: второе чтение той же книги тем же человеком не считается.

#### `artifact.found`

Найден предмет, который что-то открывает на сайте.

```json
{
  "id": "d4e5…", "v": 1, "type": "artifact.found",
  "at": "2026-08-17T14:20:00Z",
  "player": { "uuid": "069a…", "name": "Arsen" },
  "artifactId": "хронометр"
}
```

Что именно откроется — решает сайт по твоему файлу `story.json`. Плагин про это не знает.

**Ключ разблокировки — это и есть `artifactId`.** `api` кладёт его в `unlocks.json` как есть, не заглядывая
в сюжет. Первая находка артефакта побеждает: повторные не переписывают ни время, ни имя нашедшего.

#### `note.published`

Игрок написал книгу с пером и ввёл `/note`.

```json
{
  "id": "77aa…", "v": 1, "type": "note.published",
  "at": "2026-08-16T22:05:00Z",
  "player": { "uuid": "069a…", "name": "Arsen" },
  "note": {
    "title": "День третий",
    "pages": ["Вышли к обрыву…", "За ним долина…"],
    "draft": false
  }
}
```

Ограничения: не больше 50 страниц, не больше 1000 символов на страницу, не больше 20 записей
в сутки от одного игрока. Всё, что сверх — `api` отклоняет с понятной ошибкой.
Черновик (`draft: true`) сохраняется, но в публичные файлы не попадает.

#### `stats.snapshot`

Полный слепок статистики игрока. Раз в пять минут для тех, кто в сети, и один раз при выходе.

```json
{
  "id": "5b0f…", "v": 1, "type": "stats.snapshot",
  "at": "2026-08-16T20:00:00Z",
  "player": { "uuid": "069a…", "name": "Arsen" },
  "stats": {
    "playtimeMinutes": 412,
    "distanceCm": 120400000,
    "blocksMined": 184902,
    "blocksPlaced": 63120,
    "mobsKilled": 1042,
    "deaths": 37
  }
}
```

**Именно слепок, а не прирост.** Прирост требует, чтобы ни одно событие не потерялось, — слепок
не требует ничего: последний по времени просто перекрывает предыдущий. Это делает всю систему
устойчивой к сбоям сети.

Откуда берутся числа в ванильном майнкрафте:

| Поле | Источник |
| --- | --- |
| `playtimeMinutes` | `Statistic.PLAY_ONE_MINUTE` |
| `distanceCm` | сумма `WALK_ONE_CM`, `SPRINT_ONE_CM`, `SWIM_ONE_CM`, `BOAT_ONE_CM`, `HORSE_ONE_CM` |
| `blocksMined` | сумма `MINE_BLOCK` по всем материалам |
| `blocksPlaced` | считаем сами по событию установки блока: ванильного счётчика нет |
| `mobsKilled` | `Statistic.MOB_KILLS` |
| `deaths` | `Statistic.DEATHS` |

#### `place.revealed`

Ручной рычаг для тебя: команда в игре открывает метку на карте, не дожидаясь находки.

```json
{
  "id": "1a2b…", "v": 1, "type": "place.revealed",
  "at": "2026-08-18T12:00:00Z",
  "placeId": "храм-в-джунглях",
  "by": "admin"
}
```

Нужен на случай, когда что-то пошло не так посреди сезона, а чинить надо сейчас.

## Часть 3. Файлы, которые читает сайт

`api` раз в минуту перезаписывает их целиком. Сайт читает статику и не знает, откуда она взялась.

Каждый файл содержит поле `updatedAt` — сайт по нему показывает, насколько данные свежие.

### `/data/status.json`

```json
{
  "updatedAt": "2026-08-16T20:01:00Z",
  "serverOnline": true,
  "online": [{ "uuid": "069a…", "name": "Arsen" }],
  "season": { "startsAt": "2026-10-15T18:00:00Z", "storyEndsAt": "2026-10-22T23:59:00Z" }
}
```

Даты сезона **события не приносят**: их знает не игра, а настройка `api`. Пока они не заданы,
поле равно `null`, и сайт обходится без отсчёта.

`serverOnline` считает сам `api` по свежести последнего heartbeat: три минуты тишины — сервер
выключен. Вместе с ним пустеет `online`, иначе упавший сервер навсегда оставил бы игроков в сети.

### `/data/crew.json`

```json
{
  "updatedAt": "2026-08-16T20:01:00Z",
  "players": [
    {
      "uuid": "069a…",
      "name": "Arsen",
      "firstSeen": "2026-10-15T18:04:00Z",
      "lastSeen": "2026-10-20T22:31:00Z",
      "online": true,
      "stats": {
        "playtimeMinutes": 412, "distanceCm": 120400000,
        "blocksMined": 184902, "blocksPlaced": 63120,
        "mobsKilled": 1042, "deaths": 37
      },
      "recordsFound": 3,
      "recordsRead": 11
    }
  ]
}
```

Здесь **нет** артов, биографий и соцсетей — они твои и живут в `src/content/crew.json`.
Сайт склеивает два источника по `uuid`.

### `/data/records.json`

```json
{
  "updatedAt": "2026-08-16T20:01:00Z",
  "found": [
    {
      "recordId": "храм-1",
      "foundBy": { "uuid": "069a…", "name": "Arsen" },
      "foundAt": "2026-10-16T21:47:03Z",
      "readBy": 7
    }
  ]
}
```

Текста записи здесь нет — он в твоём `story.json`. Сайт показывает текст только для тех записей,
что встречаются в этом файле.

### `/data/notes.json`

```json
{
  "updatedAt": "2026-08-16T20:01:00Z",
  "notes": [
    {
      "id": "77aa…",
      "author": { "uuid": "069a…", "name": "Arsen" },
      "at": "2026-10-16T22:05:00Z",
      "title": "День третий",
      "pages": ["Вышли к обрыву…", "За ним долина…"]
    }
  ]
}
```

### `/data/unlocks.json`

```json
{
  "updatedAt": "2026-08-16T20:01:00Z",
  "unlocked": {
    "chronometer": { "at": "2026-10-17T14:20:00Z", "by": "Arsen" },
    "map": { "at": "2026-10-15T19:00:00Z", "by": "admin" }
  },
  "places": ["храм-в-джунглях", "первая-гавань"]
}
```

Сайт рисует раздел, только если соответствующий ключ здесь есть. Всё остальное показывает
запертым, с силуэтом и подписью «ещё не найдено» — так игрок видит, что впереди что-то есть.

## Часть 4. Твои файлы

Правишь их в репозитории, они уезжают на сайт вместе со сборкой. Плагин про них не знает.

### `story.json` — сюжет

```jsonc
[
  {
    "id": "храм-1",
    "title": "Первая табличка",
    "chapter": 1,
    "text": "Мы нашли её у входа…",
    "opens": ["place:храм-в-джунглях", "record:храм-2"],
    "unlocks": "chronometer"
  }
]
```

- `opens` — что показать на сайте, когда запись найдена: метку на карте или намёк на следующую главу.
- `unlocks` — какой раздел сайта включить.

### `places.json` — метки на карте

```jsonc
[
  { "id": "храм-в-джунглях", "x": 0.42, "y": 0.61, "title": "Храм в джунглях", "text": "…" }
]
```

Координаты **не игровые, а доли от размера картинки карты** — от нуля до единицы. Так метки не
поедут при смене масштаба, и заодно настоящие координаты не утекают наружу.

### `titles.json` — правила званий

```jsonc
[
  { "id": "первопроходец", "label": "Первопроходец", "rule": "maxRecordsFound", "frame": "gold" },
  { "id": "ходок", "label": "Ходок", "rule": "maxDistance", "frame": "silver" }
]
```

Звание получает тот, кто первый по показателю. Ручные звания можно проставить прямо в `crew.json` —
они важнее автоматических.

## Часть 5. Что решено и что ещё нет

**Решено:**

- базы данных нет, всё на файлах — при пятнадцати игроках и шести неделях этого достаточно;
- `season_id` не нужен: прошлые сезоны не хранятся;
- сайт только для чтения, записи игроков приходят из игры книгой;
- список онлайна берётся из heartbeat, а не из join и leave;
- статистика передаётся слепками, а не приростом;
- исследованные чанки не отслеживаются, карта открывается метками мест;
- ключ разблокировки равен `artifactId`, сюжет за ним знает только сайт;
- даты сезона приходят из настройки `api`, а не из событий;
- нашедший запись не считается прочитавшим её: он показан отдельной строкой;
- архив на сайте открывается самим фактом первой находки, отдельного ключа для него нет.

Эти пять пунктов уточнены не на бумаге, а кодом: `tools/sample` сводит поток событий в снимки
по правилам из этого документа, и каждое правило закрыто тестом.

**Ещё не решено:**

- нужна ли авторизация на сайте во втором этапе и что она даст, кроме правки соцсетей;
- как выглядит конец сезона на самом сайте: заморозить как есть или показать итоги;
- нужен ли рейтинг в открытую или только звания.
