# Настройка CI

`checks.yml` — проверки, которые до сих пор запускались только руками: тесты,
типы, линтер, формат и сборка сайта, плюс сборка плагина на Java 21.

## Почему она лежит здесь, а не в `.github/workflows/`

GitHub не принимает пуш, который создаёт или меняет файл в `.github/workflows/`,
если у токена нет права `workflow`. У токена, которым пушат из этой машины,
его нет — и пуш отвергался целиком, вместе со всей остальной работой.

## Как включить

Любым из двух способов, оба одноразовые.

**Через терминал** — выдать право и перенести файл:

```bash
gh auth refresh -s workflow
mkdir -p .github/workflows
git mv docs/ci/checks.yml .github/workflows/checks.yml
git commit -m "проверки в CI"
```

**Через сайт** — открыть на github.com вкладку Actions, «set up a workflow
yourself», вставить содержимое `checks.yml` и сохранить. Веб-редактору право
`workflow` не нужно: оно у него уже есть.

После этого файл здесь не нужен — он должен остаться в одном месте, иначе
две копии разойдутся.
