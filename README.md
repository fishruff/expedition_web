# Expedition

Сезонный Minecraft-сервер про исследование неизвестного острова и **сайт-дневник**, который
раскрывается вместе с игроками. Система состоит из трёх частей, и все три живут в этом
репозитории — потому что их связывает [контракт обмена](./docs/contract/api-v1.md),
а его нельзя менять в одностороннем порядке.

| Часть | Где | Что делает |
| --- | --- | --- |
| ExpeditionCore | `plugin/` | Плагин Paper: замечает, что произошло в игре, и шлёт события |
| api | `api/` | Принимает события, раз в минуту пересобирает снимки |
| Сайт | корень репозитория (`src/`, `public/`) | Превращает снимки в дневник экспедиции |
| Сервер | `server/` | Игра и приёмник в докере: `docker compose up -d` |

Сайт лежит в корне по историческим причинам: репозиторий начинался с него. Всё, что не `plugin/`
и не `api/`, — это сайт.

## Запуск

```bash
npm install
npm run dev      # дев-сервер на http://localhost:5173
npm run build    # типы + продакшн-сборка в dist/
npm run preview  # локальный просмотр собранного
npm test         # vitest
npm run lint     # ESLint

npm run data:sample   # показательные снимки из игры в public/data
npm run season:check  # сверка живых снимков с текстами владельца

EXPEDITION_KEY=secret-key npm run api  # приём событий от плагина на :4000
```

Это команды разработки. Сезон поднимается целиком из `server/`: там игра и приёмник
в одной сети докера, ключ из `.env`, снимки — в тот же `public/data`. Подробности —
[`server/README.md`](./server/README.md).

```bash
cd server && cp .env.example .env && docker compose up -d
```

Сайт работает и без снимков — это нормальный режим до запуска плагина. Но разделы удобнее
верстать на живых данных, поэтому `data:sample` раскладывает по контракту правдоподобный сезон:
экипаж, находки, записи книгой, часть разделов открыта, часть заперта. В репозиторий эти файлы
не попадают: во время сезона их пишет `api`.

Снимок стареет: через три минуты сайт честно скажет «сервер выключен» — это правильное поведение,
просто запусти команду ещё раз.

`season:check` сверяет то, что пришло из игры, с тем, что описано в `src/content`. Плагин про сюжет
не знает и шлёт любой номер, `api` в сюжет не заглядывает — расходятся они молча, и на сайте это
выглядит не ошибкой, а находкой без текста. Запускать перед стартом сезона и всякий раз, когда
предмет помечен новым номером.

Нужен Node.js 22.22+ (требование jsdom в тестах; сама сборка живёт и на 20.19+).

## Структура

```
src/
├── app/          роутер и карта путей
├── scene/        сцена: стол, предметы, расчёт масштаба
├── content/      JSON с данными и слой валидации
├── data/         снимки из игры: чтение, склейка, разблокировки
├── shared/       конфиг сайта и чистые функции (отсчёт, склонения)
├── styles/       токены, миксины, глобальные стили
└── main.tsx
public/
├── assets/       пиксельные ассеты: тайлы, рамки, предметы
├── data/         снимки из игры (не в репозитории)
└── fonts/        Monocraft (OFL), с кириллицей
tools/
├── sample/       поток событий сезона и сведение его в снимки
├── check-season.ts  сверка снимков из игры с текстами владельца
├── pixelize.py   приведение сгенерированного арта к настоящему пикселю
└── gen_frames.py рамки, нарисованные кодом
api/
├── src/          приём событий, журнал, сборка снимков
└── Dockerfile    образ приёмника: только Node, без зависимостей
plugin/
└── ExpeditionCore/  плагин Paper (Java 21, Gradle)
server/
└── docker-compose.yml  игра и приёмник в одной сети; мир и jar не в репозитории
```

## Плагин

```bash
cd plugin/ExpeditionCore
./gradlew build          # результат в build/libs/ExpeditionCore-0.1.0.jar
```

Собранный `jar` кладётся в `plugins/` сервера. Требуется Java 21 — это требование самой 1.21.

## Правила пиксельного оформления

Их нарушение сразу видно на экране — картинка начинает мылить.

- **Масштаб только целый.** Живёт в CSS-переменной `--s`, считается в `src/scene/useScale.ts`.
  Размеры задаются через функцию `px(n)` из миксинов, а не в пикселях напрямую.
- **Ассеты хранятся в родном размере** — маленькими. Браузер увеличивает их целым числом раз.
  Большой файл не улучшает картинку, а ухудшает: при дробном увеличении точки расплываются.
- **Только PNG.** JPEG размазывает пиксельные края.
- **Три типа ассетов**, каждый со своим поведением при адаптиве:
  - *тайл* — повторяется и заполняет любой размер (дерево, бумага), миксин `tile()`;
  - *рамка из девяти слоёв* — тянется под содержимое, углы целы (панели, книга), миксин `nine-slice()`;
  - *предмет* — не тянется никогда, только целый масштаб (компас, часы, арт игрока).
- **Межбуквенное расстояние — целыми точками**, через `px(n)`, а не в `em`. Доля от кегля
  даёт дробный шаг, буквы съезжают с сетки и мылят: `УВЕДОМЛЕНИЯ` превращается
  в `УВЕДОМЛЕМИЯ`. Та же причина, что и у целого масштаба, только заметна не сразу.
- **Никаких размытий и скруглений.** Ни `border-radius`, ни размытых теней.
- **Анимации ступенчатые** (`steps()`), плавность выдаёт непиксельность.
- Контент правится в `src/content/*.json`, разметку для этого трогать не нужно.
